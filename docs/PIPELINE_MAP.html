System map

Blog Translation Pipeline

One agent, four sequential steps, split across two directories: tools/translation_agent/ scans blog repositories and fills in missing-language posts with an LLM; tools/quality_agent/ audits every translation already on disk and force-retranslates the ones an LLM judges unusable. The two pipelines never call each other directly — they hand off through Google Sheets and the shared Git repositories.

Every script named above, grouped by stage

StageFileResponsibility
Step 1scan_missing_translations.pyWalks the 6 blog repos, finds missing index.{lang}.md files, writes the scan & history sheets.
Step 2translator.pyTranslationOrchestrator plus the Frontmatter, Content, and Platform agents (Fig. 2).
Step 1–2git_repo_utils.pyClones or pulls the six blog repositories via a GitHub PAT.
Step 1–2io_google_spreadsheet.pyReads and writes the scan sheet via a Google service account.
Step 1–2utils.pyPosts job metrics to two Google Apps Script webhooks.
Step 1–2config.pySingle source of truth for domains, languages, sheet IDs, and env-var secrets.
Step 3Aquality_scanner.pyHeuristic word-overlap Error % per translated file, skipping code and shortcodes.
Step 3Bquality_validator.pyAI Error % on a 20-paragraph sample; also returns the RETRANSLATE / KEEP decision and reason.
Step 4quality_retranslator.pyForce-retranslates rows flagged RETRANSLATE via TranslationOrchestrator; sets Status = Fixed.
Step 3–4lang_guard.pyLanguage-code normalization, validation, and RTL detection shared by the quality scripts.
